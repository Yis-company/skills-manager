Proposed changes

  • Add a short tracked hook and a small installation script, using existing Node/Bun tooling and no dependency or task runner. Add a `prepare` lifecycle entry without replacing any existing lifecycle behavior. Installation resolves the effective Git hook location, installs only when safe, is repeatable, and never silently overwrites a foreign hook or changes `core.hooksPath`. Refuse with an actionable message on conflicting hook or unsupported configuration; don't claim protection when installation is skipped. Handle linked worktrees and paths with spaces. Document install, prerequisites, checks, and how to resolve a personal-hook conflict in the developer setup section of README.
  • Hook runs from the project root, fails on a missing required tool or first failed command, and runs: `bun run format:check`, `bun run lint`, a new `typecheck` script invoking `tsc -b`, `bun run test`, and `cargo fmt --manifest-path src-tauri/Cargo.toml --check`. TypeScript build mode includes app, tooling and E2E type configurations and writes incremental metadata under ignored `node_modules/.tmp`, but emits no app code. This avoids the Vite build output while retaining CI's TypeScript check. The checks inspect the working tree, not an exact pushed commit; Git can bypass hooks explicitly and installs can skip lifecycle scripts.
  • Keep frontend CI's full build and Playwright, changeset checks, macOS/Windows Rust tests, and Linux Rust formatting and all-target Clippy unchanged. Native compile/tests may require platform libraries, cached crates, network, and substantial time; local Rust formatting supplies a proportionate native guard, not cross-platform validation. No Turbo, remote cache, Docker producer, new framework, custom hashing, or app changes.
