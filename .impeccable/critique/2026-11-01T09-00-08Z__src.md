## What works

- Persistent host selection, remote context, and project paths make operating scope a first-class concern.
- Instruction/MCP previews, explicit removal lists, and restore safety points provide useful review patterns.
- Search, filters, bulk actions, and Cmd/Ctrl+K serve experienced users without forced onboarding.

## Priority issues

1. **[P1] Preset pills hide the scope and consequences of switching.** Global/agent workspaces use the same pill presentation as project add/remove operations. After the first reviewed switch, the removal preview is skipped (`src/components/PresetBar.tsx:185`, `src/hooks/usePresetSwitch.tsx:23`). An apparently local action can change the shared active preset and remove direct additions. Separate view, project-add, and shared-switch wording; review affected hosts, agents, additions, and removals whenever removals occur. **Commands:** `$impeccable clarify`, `$impeccable harden`.

2. **[P1] Conflict resolution offers winners without the changes.** Sync review presents names, host provenance, and keep actions, but no version comparison (`src/views/sync/Review.tsx:60`). Users must leave the decision or guess. Add Compare changes before resolution, show both versions and paths, and explain the result and recovery. **Commands:** `$impeccable shape`, `$impeccable harden`.

3. **[P1] Inspection and confirmation have keyboard/semantic gaps.** Skill detail activation uses clickable divs (`src/components/LibrarySkillCard.tsx:97`, `src/components/LibrarySkillRow.tsx:70`); view buttons lack labels (`src/views/MySkills.tsx:1321`); the shared confirmation component lacks dialog semantics and focus management (`src/components/ConfirmDialog.tsx:62`). Make the title a native detail-opening control, label toolbar buttons, expose hover actions on focus, and standardize accessible dialog focus entry, containment, restoration, and close. **Commands:** `$impeccable harden`, `$impeccable audit`.

4. **[P1] Help reinforces the obsolete preset model.** The guide says presets act only on the current agent scope and are one-time copies; it also points users to Git Backup in Settings (`src/i18n/en.json:25`, `src/i18n/en.json:29`). This conflicts with the current shared active-preset model. Rewrite around Library, viewed preset, active shared preset, and actual agent copies; put short scope guidance beside the controls. **Commands:** `$impeccable clarify`, `$impeccable onboard`.

5. **[P2] Library obscures the distinction between preset membership and agent presence.** “Enabled/Available” and the primary switch describe membership in the viewed preset, while agent icons show actual presence (`src/views/MySkills.tsx:1222`, `src/views/MySkills.tsx:1495`, `src/components/LibrarySkillCard.tsx:198`). Name the viewed and active presets beside the content, use In preset / On agents labels, and separate browsing preferences from operational actions. **Commands:** `$impeccable layout`, `$impeccable distill`.

## Cognitive load and emotional journey

Search, grouping, and progressive disclosure work. Five checklist failures concentrate around hierarchy, mixed mutation/selection, unbounded choices, scope recall, and omitted conflict evidence. Preset lists, per-skill agent actions, and the mixed toolbar present more than four options; the problem is mixed meanings, not the mere number of inventory items.

The familiar shell builds confidence; uncertainty rises at preset switching and conflict resolution. Preserve the calm tone and end consequential operations with what changed, where, and how to recover.
