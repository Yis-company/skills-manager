# Domain documentation

Use one domain context for the application and its shared Rust core.

Before domain exploration, read CONTEXT.md when present: it is the established vocabulary authority. Read relevant docs/adr decisions and the linked Linear map or ticket before proposing changes. Follow GLOSSARY.md or GLOSSARY-MAP.md if deliberately introduced later, preserving the existing authority.

When a referenced file is absent, proceed with repository and tracker evidence. Create domain records only when real terms or decisions are resolved. Setup creates no empty glossary, map or ADR.

Use established terms in discussions, issues, tests and proposals. Surface conflicts with recorded decisions. Record resolved terms in the existing domain document; add an ADR only when warranted.
