# Local MCP setup in Codex and Claude Code

Research for Skills Manager (Agents Manager) · 2026-11-19 · Local, interactive clients unless noted.

**For “Set up this project,” the lowest-friction path is one-time registration per client on the host that runs it, followed by a call with the intended workspace supplied explicitly.** Agents Manager can write the registration as part of an authorized setup flow. The client starts the subprocess and discovers the tools. The user handles any trust, server approval, or client-policy prompt. Once connected, a clear request authorizes routine Agents Manager writes under the agreed product behavior. The client’s permission settings still govern whether it can dispatch the call. [OpenAI MCP guide](https://learn.chatgpt.com/docs/extend/mcp) · [Claude Code MCP quickstart](https://code.claude.com/docs/en/mcp-quickstart) · [Claude Code permissions](https://code.claude.com/docs/en/permissions)

| Step and owner | Codex | Claude Code |

[MCP guide](https://learn.chatgpt.com/docs/extend/mcp#configure-with-configtoml) · [CLI reference](https://learn.chatgpt.com/docs/cli/reference#codex-mcp) | A user or authorized installer can run `claude mcp add --transport stdio --scope user skills-manager -- /absolute/path/to/launcher`. Place client flags before `--`. JSON entries use `mcpServers` with `type: "stdio"`, `command`, and optional `args` and `env`. [Stdio registration](https://code.claude.com/docs/en/mcp#option-3-add-a-local-stdio-server) · [Quickstart](https://code.claude.com/docs/en/mcp-quickstart) |
| Choose where to register. **User or authorized installer** chooses the scope. A **maintainer** can ship shared project config. | CLI registration writes the user config at `~/.codex/config.toml` by default. For repo-specific registration, write `.codex/config.toml` under the project. Codex reads project layers only for a trusted project. The user grants workspace trust when needed. [CLI reference](https://learn.chatgpt.com/docs/cli/reference#codex-mcp) · [Configuration precedence](https://learn.chatgpt.com/docs/config-file/config-basic#configuration-precedence) | `--scope user` is cross-project and private in `~/.claude.json`. Duplicate names resolve local, then project, then user, with managed policy able to take precedence. A typical interactive first run asks the user to trust the workspace and approve servers from `.mcp.json`; existing approvals and applicable policy affect what appears. [Installation scopes](https://code.claude.com/docs/en/mcp#mcp-installation-scopes) · [Project approvals and trust](https://code.claude.com/docs/en/mcp#project-server-approvals-and-workspace-trust) |

OpenAI documents a restart after saving a server in the desktop app and IDE extension. In the CLI, reopen the session after registration if the server is absent. [OpenAI MCP guide](https://learn.chatgpt.com/docs/extend/mcp) · [CLI slash commands](https://learn.chatgpt.com/docs/reference/slash-commands) | Start a new session after editing `.mcp.json`. For stdio, the client owns the subprocess and communicates over its standard streams. There is no separate listener or MCP OAuth step for the local launcher. A dependency behind an individual tool may still require its own authentication. ## Workspace context and tool permissions

- **Codex workspace.** The documented `cwd` sets the process launch directory. In the pinned 0.170.0 source, the stdio launcher falls back to the local execution environment’s working directory or a host fallback when `cwd` is omitted. The client initialization reviewed for that release does not advertise MCP roots. A start directory is a useful hint for a single project, and its association with a particular tab, worktree, or later tool call needs verification on each supported surface. [Config reference](https://learn.chatgpt.com/docs/config-file/config-reference) · [Local launcher](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/rmcp-client/src/stdio_server_launcher.rs#L418-L440) · [Runtime context](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/core/src/session/mcp.rs#L158-L175) · [Client initialization](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/codex-mcp/src/rmcp_client.rs#L1305-L1341)
- **Claude Code workspace.** The client injects `CLAUDE_PROJECT_DIR` into the child at launch. It represents the project root and stays stable when additional working directories change. The client documents answering `roots/list` with its launch directory and additional working directories, with change notifications. The protocol deprecated roots in revision 2026-07-28 and recommends explicit tool parameters, resource URIs, or server configuration for new integrations. Roots convey context, while enforcement belongs to the server and its runtime. [Claude Code stdio context](https://code.claude.com/docs/en/mcp#option-3-add-a-local-stdio-server) · [MCP roots specification](https://modelcontextprotocol.io/specification/2026-07-28/client/roots)
- **Codex tool calls.** The user or administrator controls server availability and tool exposure. `enabled_tools` filters the catalog and `disabled_tools` is applied afterward. Set `default_tools_approval_mode` at server level or `tools.<tool>.approval_mode` for a specific tool. In the pinned source, `prompt` requests approval, `writes` requests it for tools without `readOnlyHint: true`, `approve` skips this approval check, and `auto` uses tool annotations. The user or configured reviewer handles eligible approval requests. [MCP config options](https://learn.chatgpt.com/docs/extend/mcp#other-configuration-options) · [Approval implementation](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/core/src/mcp_tool_call.rs#L2672-L2697) · [Auto-review](https://learn.chatgpt.com/docs/sandboxing/auto-review)
- **Claude Code tool calls.** The client applies its permission mode and `deny`, `ask`, then `allow` rules. Rules can target `mcp__<server>__<tool>` or `mcp__<server>__*`. The user approves when the active mode or rules require it. A server author can force explicit human approval for a specific tool using `_meta["anthropic/requiresUserInteraction"]: true`. That flag takes precedence over a standing allow and is unsuitable for the agreed routine-write flow. [MCP tool rules](https://code.claude.com/docs/en/permissions#mcp-tools) · [Server-required approval](https://code.claude.com/docs/en/mcp#require-approval-for-a-specific-tool)
- **Prompts serve different purposes.** The user’s natural-language request tells the model what to do. Guidance from server initialization in Codex and user-invoked MCP prompt commands in Claude Code can help the assistant find the workflow. Claude Code exposes prompts as `/servername:promptname`; an equivalent Codex MCP prompt command was not established by the docs reviewed. Structured elicitation is a separate server-to-client request for missing input. Claude Code presents form or URL dialogs when supported. Codex App Server exposes an elicitation request to its host UI, subject to the configured approval policy. Either client can still require tool-call approval independently. [Codex MCP guide](https://learn.chatgpt.com/docs/extend/mcp) · [Codex App Server API](https://learn.chatgpt.com/docs/app-server#api-overview) · [Codex configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference) · [Claude Code MCP prompts](https://code.claude.com/docs/en/mcp#use-mcp-prompts-as-commands) · [Claude Code elicitation](https://code.claude.com/docs/en/mcp#respond-to-mcp-elicitation-requests)

## Restart and recovery

| Situation | Codex | Claude Code |
| --- | --- | --- |
| New or edited registration | The **user** restarts the desktop app or extension after saving. For CLI registration, opening a fresh session is the practical fallback if the active session still lacks the server. The CLI guide documents inspection with `/mcp`. An **App Server host** can use `config/mcpServer/reload` to reread disk config and queue a refresh for loaded threads. That API does not establish an equivalent user-facing reconnect command. [Setup](https://learn.chatgpt.com/docs/extend/mcp) · [App Server API](https://learn.chatgpt.com/docs/app-server#api-overview) | The **user** starts a fresh session to load an edited `.mcp.json`. In supported versions, `/cd` also applies the destination’s project configuration when moving the session to another directory, subject to trust and server approval. [Quickstart](https://code.claude.com/docs/en/mcp-quickstart) · [Session directory changes](https://code.claude.com/docs/en/permissions#move-the-session-to-another-directory) |
| Existing stdio server exits or fails startup | The **user** can inspect the session with `/mcp verbose`, fix the launcher or environment, and reopen the client session if necessary. A general automatic stdio recovery guarantee or a per-server CLI reconnect action was not verified. App Server exposes startup status to its host. [CLI MCP diagnostics](https://learn.chatgpt.com/docs/developer-commands#list-mcp-tools-with-mcp) · [App Server API](https://learn.chatgpt.com/docs/app-server#api-overview) | In the interactive terminal, the **user** chooses the server in `/mcp` and selects **Reconnect**. `/mcp reconnect all` retries failed servers in v2.1.284+. In `claude -p` or the Agent SDK, the **client** restarts a subprocess that exited mid-session on the next call to its tool. First-connect failure requires a new CLI run or an SDK reconnect initiated by the application. [Stdio recovery](https://code.claude.com/docs/en/mcp#stdio-servers-that-exit-or-fail-to-start) · [Retry failed servers](https://code.claude.com/docs/en/mcp#retry-failed-servers-yourself) |

A connected Claude Code server can notify the client when its tool, prompt, or resource catalog changes. Claude Code refreshes the catalog without requiring the user to reconnect. This applies to changes advertised by the running server. [Dynamic tool updates](https://code.claude.com/docs/en/mcp#dynamic-tool-updates)

## Implications for “Set up this project”

1. **Bootstrap outside the MCP call.** Offer registration from the existing Agents Manager setup entry point. User scope gives an individual one registration per chosen client on that host. Keep project scope available when a maintainer wants to share the registration with the team. A session needs the server to be available before it can ask that server to configure itself. Today the repo documents Dashboard setup for the `manage-skills` skill and CLI, and a separate workflow for deploying MCP definitions. [Repo README](https://github.com/Yis-company/skills-manager/blob/494286da67248797bcde5153ccf035611dbd22ee/README.md#L91) · [Agents Manager MCP workflow](https://github.com/Yis-company/skills-manager/blob/494286da67248797bcde5153ccf035611dbd22ee/AGENTS-MANAGER.md#L15)
2. **Send the target workspace with the request.** Have the assistant pass the selected worktree’s absolute path or an established Agents Manager project ID that resolves to that directory. Agents Manager resolves the target on the execution host, validates it, and returns the actual path and applied changes. Use runtime directory hints to assist discovery. Ask the user to choose only if the intended project remains ambiguous.
3. **Keep the first journey narrow within the agreed whole-product scope.** Let a clear “Set up this project” request carry routine-write intent through the existing product operations. Keep the client’s own prompts visible. If a connection drops during a write, inspect product state before retrying so the user can tell whether setup was already applied.

## Evidence boundary

**Exercised locally:** `codex --version` and `codex mcp add --help` on Codex CLI 0.170.0, and `claude --version` and `claude mcp add --help` on Claude Code 2.1.327. These confirmed the stdio command forms and Claude Code’s default local scope. Repo context is from the documentation visible at checkout HEAD `494286d`.

**Documented or source-inspected:** registration writes and precedence, trust, subprocess startup and workspace context, tool discovery and approval, and refresh or reconnect behavior. No MCP registration, handshake, live tool call, approval dialog, reconnect, or desktop/IDE behavior was exercised. No working configuration or workspace files were changed. The remaining end-to-end check is one interactive run per target client using a fixture project/worktree, a read-only status tool, a reversible routine write, and a controlled subprocess exit.
